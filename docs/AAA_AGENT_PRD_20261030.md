# AAA 卷小助智能归档 Agent 开发 PRD

版本：1.2｜日期：2026年10月30日｜状态：开发设计基线，新增能力尚待实现与验收

面向产品负责人、开发人员及验收人员。目标是把 AAA 从依赖逐页分类和人工核对的归档流程，升级为能够选择识别工具、追踪填写依据、自主复核并积累经确认经验的归档助手。用户导入真实卷宗后得到可检查的完整草稿，仅对系统无法可靠解决且影响成果的疑点集中作决定。

本 PRD 的功能条目是开发要求，不是当前版本的能力声明。本文不批准新一轮真实材料云端测试、自动部署、恢复巡检或上传客户材料至公开仓库。

## 1 产品目标与范围

### 1.1 核心目标

- 减少人工负担：正常路径是导入、开始、查看成果；需正式成卷时最多一次最终确认。已配置的云端授权按实际有效范围复用，不每页重复询问。
- 适应真实材料：处理规范扫描件，也能识别手写、模糊、方向异常、截图、跨页表格和混杂文件；无法读清时不猜填。
- 内容可靠：能区分文书身份、目录位置、案件归属、材料存在、签署状态和字段可采纳性。
- 填表可交付：有依据的栏目充分填写；依法或按律所约定需要手填的区域留白；原表布局稳定。
- 持续改进：从实际纠错形成有适用范围、验证记录及版本的经验，而非无限追加提示词或自行修改生产代码。

### 1.2 本期与后续

本期覆盖整卷 PDF 与混合 PDF、Word、图片文件夹；保留民事、行政、刑事、非诉、顾问五类业务。第一阶段以民事打通完整机制，其他四类按各自原表和材料特点逐类验收，不能沿用民事通过结论。

本期采用现有 DeepSeek 云端接口和本地文件工具；预留可替换 OCR、视觉模型及本地 Ollama 接口。明确区分“接口可连接”和“本地卷宗已通过验收”。

后续再评估本地模型适配、并发扩容与单机安装包。暂不实施模型微调、任意网络检索客户资料、自动改代码、自主安装工具、多 Agent 集群，以及扫描整个电脑查找案件。用户指定文件夹之外的材料不得自动读取。

### 1.3 成本原则

优先复用材料缓存、识别结果及现有原表模块。额外复核限定到相关页面或字段，不因一次疑点重跑整卷。开源组件仍有集成、维护、模型推理及硬件成本；本地推理不等于零成本。

## 3 用户角色与主流程

普通助理负责导入、查看成果及作必要选择；承办律师负责有实质影响的业务判断；管理员负责模型、预算、模板、权限及经验发布。同一人员可以兼任，但权限应显式分配。

```text
导入材料 → 材料检查 → 识别与结构整理 → 字段证据与综合填写
                                         ↓
                               有限自主复核与原表质检
                                         ↓
                       草稿成果＋集中疑点／补充清单
                                         ↓
                       用户选择或补件 → 受影响部分续跑
                                         ↓
                             一次最终确认 → 定稿成果
```

首页只保留导入、开始和历史入口。处理中显示简短阶段、已处理数量和可取消入口；不展示提示词、工具调用堆栈或假进度。完成后先展示成果及必须处理的事项，细节按需展开。助理形象承载对话入口，不重复弹窗或主动制造干扰。

## 4 功能需求

### F01 材料接收与质量检查

为每个原文件生成稳定 ID、哈希、页数及版本。原文件只读；转换、旋转、裁切、增强均生成派生副本，并记录转换链及原图坐标映射。Word 转换须保留原文件，页码引用绑定具体转换版本。

| 材料情况 | 系统动作 | 失败处理 |
| --- | --- | --- |
| 原生文字 PDF | 读取文字层并核对图像与文字一致性 | 文字层无效或错位时转视觉/OCR，不假设一定正确 |
| 横向、倒置、倾斜 | 判断方向，创建识别副本并校正 | 方向仍不确定时比较候选；不改变原件内容 |
| 模糊、小字、遮挡 | 查看局部原始分辨率、调整裁切、比较其他来源 | 不用生成式修复补造姓名、数字或笔画；缺依据留白 |
| 手写印刷混合 | 分区域读取，保留候选读法与原图位置 | 关键姓名、金额、日期不能仅凭上下文猜测 |
| 截图、聊天、照片 | 识别内容用途、时间及归属，保留上下文 | 不把聊天主张直接写成已证实事实 |
| 损坏、加密、转换失败 | 标出受影响文件和可执行处理选项 | 不静默跳过，不将部分导入显示为全部成功 |

识别纠偏与成果显示方向分开：确认方向后可非破坏性调整 PDF 显示旋转并记录；去噪、锐化等增强图不替代原始证据。无法判断的原页保持原貌。

### F02 四层文档结构

数据层建立“目录项目—材料组—独立文书—源页面”。一组证据可以含合同、借据、登记证明、计算表和截图；同属证据不等于同一文书。目录排序与文书身份分别存储。

整卷模式综合标题、条款衔接、内部页码、版式、独立落款、用途和程序阶段判断边界。前批识别结果只是候选，当前页的新证据可以推翻它。相同姓名、案号、合同号或相邻页面均不能单独证明应合并。

文件夹模式先保留输入文件边界，再检查文件内部是否混有多份文书。跨文件关联只建立逻辑关系，不物理合并或丢弃原文件；明确属于同一文书且有衔接依据时才能形成跨文件文书单元，来源需逐页可回溯。

证据清单作为导航：提取名称、顺序、页数及证明内容，与后续材料匹配；区分找到、部分找到、未找到和有冲突。清单不能证明附件实际存在，不能推定后面所有页面都是证据。

边界不清但不影响归档位置和字段采纳时，保留临时子段并按组展示；若影响合同条款范围、主体、收费或事实提取，则进入自主复核，仍不明才询问用户。

2026-10-30 用户确认：有明确附件关系的页面随同一合同保留；独立借据、登记证明、银行截图分别保留文书边界，可同属证据材料组。附件关系须有原页标注与对应合同依据，不能仅凭相邻推断。

### F03 案件归属与材料适用性

分别记录文书类型、目录位置、案件关系、程序阶段、存在状态及签署/送达/履行状态。案件关系使用本案、关联案、疑似他案、未知；不能仅因名称相同而归本案，也不能因案号不同而排除关联执行案。

疑似无关、重复、空白或无法识别页面进入待处理材料区，原页保留。去重必须有明确的保留/排除决定及来源记录；每个导入源页最终均应有去向，不得静默省略。

必要、条件必要、可选材料依据已核实的规则及适用阶段区分。无适用依据时保留未知，不能把目录空格都当必要缺件，也不能靠改成可选减少询问。规则记录来源、日期、版本、适用范围和核验状态。

### F04 受限 Agent 与工具选择

采用一个负责归档的 Agent 配合明确工具接口。模型可以选择下一步读取、比较或建议；权限、预算、版本、源页守恒和最终发布由程序校验。无需以多个 Agent 的数量衡量智能程度。

| 工具能力 | 返回内容 | 约束 |
| --- | --- | --- |
| inspect_page / inspect_region | 原页或区域图、坐标及质量标记 | 仅当前授权案件、限制分辨率和范围 |
| normalize_view | 方向/倾斜校正后的副本及变换矩阵 | 原件不可变，不能补造被遮挡内容 |
| read_text | 原生文字或 OCR 片段及位置 | 返回引擎、模型、版本、错误状态 |
| read_neighbors | 邻页及候选文书首页 | 限定范围，不自动读取其他案件 |
| search_case_evidence | 本案来源片段及相关程度 | 检索结果不是事实，需回到原件验证 |
| propose_structure | 文书边界、材料组、目录候选 | 作为建议写入，不直接覆盖人工决定 |
| propose_cell | 字段候选、依据、冲突与简述 | 不允许直接写最终成果文件 |
| validate_and_render | 事实校验、原表渲染、版式结果 | 程序执行，失败不得标成完成 |
| retrieve_experience | 当前组织且适用的已发布经验 | 旧版本、草稿经验和他组织经验不可采用 |

每个问题内部最多追加一轮有针对性的复核；每轮工具数量和总请求预算由任务策略控制，不写死成模型内自由重试。重复相同输入且无新证据的动作停止。到达预算时保留已完成内容，明确指出未解决部分，不伪装为“材料缺失”。

模型返回错误工具参数、越权路径、格式无效或工具失败时，由服务端拒绝并记录。附在合同、截图、OCR文字中的“忽略规则”等内容仅作为材料文本，不能成为执行指令。网页不具备任意执行命令、联网抓取或安装插件的 Agent 工具。

### F05 字段证据与逐格填写

每个栏目配置独立填写契约，至少含：业务类别、栏目目的、来源优先级、必读范围、允许的归纳方式、冲突处理、留白条件、容量和输出格式。优先复用 form_cell_contracts.py，并建立版本，不另起一套互相冲突的提示词。

字段处理顺序为查找来源、判断来源是否完整、绑定本案及角色、提取事实、比较冲突、生成栏内文字、检查容量。可参考历史合格写法，但不得沿用历史案件事实。用结构化事实生成摘要后，每个关键结论仍需来源支持。

| 栏目或组件 | 必须保留的业务要求 |
| --- | --- |
| 已提供立案审批表等原表 | 优先保留原件，只入卷一次；存在不等于已签署或审批；缺失组件才补填 |
| 案情简介 | 立案时视角，民事以诉状事实及诉求为主，区分当事人主张与法院认定，不混入后来结果；其他业务按自身服务目标与事项概括 |
| 委托人、当事人、对方 | 结合委托依据及诉讼角色，不默认代理原告；区分签约人、服务对象、刑事被追诉人和家属 |
| 内部合同号 | 新生成表单留空，不因识别到号码自动填写 |
| 收费标准 | 依据本案合同及补充条款；复杂风险收费只有结构和条件明确时才填；不拿贷款利率、诉讼费或收款额替代 |
| 日期 | 准确且无未决冲突才填，否则留白；审批表合同签订日默认约定仅限适用字段并标明，不扩散为法院立案日或实际审批事实 |
| 审办结果 | 全案有据程序经过与处理结果，不能只复制判决主文，不把终本视为清偿 |
| 结案小结 | 受托事项、实际工作、节点、结果及未完成事项综合撰写；无依据的开庭、回款、客户满意不写成发生 |
| 民事案件名称 | 按原告、全部被告及案由形成，不能因代理立场倒转；其他业务不机械套用 |
| 签名、审批意见、客户评价等 | 保留手填位置，Agent 不代签、不编造评价或批准 |

每格区分：有据可填、按约定留白、不适用、来源不足、来源冲突、系统提取失败、容量不足、原件保留。按约定留白不计为缺陷；系统漏提取不能改称资料缺失。缺项说明放在质检与页面，不塞进正式表格正文。

费用、姓名、日期等关键字段的自动采纳要求明确来源、角色和范围，无未决冲突；模型自报80%不作为真实准确率或单独自动确认标准。

#### 按填写任务分层阅读（2026-10-30 补充）

重要性是材料对当前栏目及核验任务的影响，不是永久等级，更不等于证据效力。全卷每页先作视觉结构和用途判断，保留入卷；深入提取按任务排序：

- 核心来源优先：起诉状、答辩状、代理意见、判决书、裁定书等支撑案件归纳；委托合同支撑受托范围及收费。刑事会见、辩护和各阶段文书，非诉/顾问实际工作及成果同样按其业务目的优先。
- 支撑来源按栏目读取：身份、授权、收费、送达、履行、金额和日期材料按具体字段需要进入补读。证据清单只是索引，不代替附件原文。
- 留存材料保留原页：已查看且明确不影响当前填写的材料可暂缓深入提取；记录“未深入读取”，不得宣称“无关”或“已全文核验”。未知、模糊、冲突以及关键来源不足不能降为无需分析。

关键文书引用、待填栏目缺乏依据、不同来源矛盾、实际履行/程序问题均可将证据材料升级为深入分析对象。例如借据或回款凭证可能影响金额及办理结果，不能因属于证据就忽略。升级应带触发原因、目标栏目、来源范围和预算；缺电话、传真等非关键可留白字段不应导致无目的重读整卷。

模型负责提出用途和优先级候选；程序限制预算、保留源页、核验字段依据。记录人工纠正后形成待审核经验，不将一次个案反馈直接写成所有案件的永久规则，不以未经校准的分数宣称识别准确率。

### F06 自主复核与集中核对

先检查结构异常，再复核相关页及字段。例如合同段包含登记证书或系统截图、单一文书突然改变标题和用途、证据清单条目被埋在其他文书中，应触发边界复核。

分类疑问与 OCR 质量疑问关联同一文书，保留全部问题 ID 和原因。卡片提供原页定位、推荐方案、两至三个可行选择及受影响的字段/目录，支持用户补充文字。来源不足时应说明“影响哪个结果”，不让用户重新阅读整卷。

用户保存成功后自动进入下一未解决事项；保存失败保留编辑内容。切换组、刷新、断网重连不丢输入或重复确认。人工选择形成版本化决定，不能由后续模型输出悄悄覆盖。

不影响归档及填写的内部拆分差异可以保留机器候选并按组展示，不升级为必须确认；实质问题不能隐藏。没有疑点不等于材料齐备，草稿可下载与正式归档条件须分开显示。

### F07 受控经验积累

经验分三类：本案决定、律所约定、通用识别方法。默认从本案决定开始；推广必须明确适用范围。不同组织之间不共享客户事实或未经批准的规则。

```text
发现实际错误 → 用户确认处理 → 提炼候选经验 → 去除个案信息
   → 检查适用条件及冲突 → 已授权实例与保留实例验收
   → 有权限人员批准发布 → 新任务按固定版本采用 → 可停用回退
```

经验内容应包括触发条件、排除条件、所需证据、建议动作、禁止推断、来源决定 ID、适用业务/模板、测试结果和版本。仅保存“用户喜欢这样做”不足以成为业务规则。

状态为 draft、validated、approved、active、retired。普通用户反馈只能形成 draft；人工批准和独立测试通过后才可 active。经验相互矛盾时暂停相关自动采用并显示冲突，不简单以最新覆盖最旧。用户明确要求留白和原件保护优先于经验建议。

经验优先级：来源真实性及系统约束 → 当前任务有效人工决定 → 适用的已批准律所规则 → 已发布通用经验 → 模型建议。历史个案决定不能自动覆盖其他案件。

任务启动时固定经验版本和规则快照；发布新经验不修改历史案件。经验回退也不自动重跑历史任务。回归测试、案例标注及发布成本均应记录。第一期采用结构化数据库及检索即可，不以向量库或微调作为启动前提。

### F08 成果与排版

输出整卷 PDF、需要补填的可编辑 Word、原表 PDF、目录链接、书签、质检清单、成果清单和 ZIP，保存到管理员指定的案件目录。没有原表时按五份系统表补填；已有原表时不能为了凑齐五份 Word 而重制原件，质量卡与须知按独立组件补齐。

原表字体、字号、段间距、行距、框线及页数按模板规格校验。先在不丢关键条件的前提下简明表述；容量仍不足时提示具体栏目，不能擅自删当事人、缩坏字体、拉框、裁字或额外分页。

草稿不新增归档页码；定稿从目录后正文第一份文件起以1连续编号，底部居中；原材料已有页码保留。目录展示编号和实际 PDF 页索引分别管理。质检注明电子页码方式与所提供纸质办法的位置要求差异。

民事、行政按实际执行材料判断17或18项，不因正文提及执行即切换。按已确认新民事目录批注，所函归第7项证据材料，普通受理通知归第12项，执行受理通知仍为执行材料；保留文书真实名称，不扩展为其他业务的统一行号规则。

生成产物先写临时位置；全部必需产物通过验证后原子发布成果清单。某个 Word、PDF 或 ZIP 失败不得显示“全部完成”；保留前次有效版本与失败原因。

## 5 建议实现架构

保留现有 Vue、FastAPI 和 SQLite，由编排层调用可替换工具。第一期在现有任务服务上实现可持久化执行；通过小范围适配验证再决定是否采用 LangGraph，不能把引入框架本身当作交付成果。

```text
Vue 页面及助理入口
      ↓
FastAPI 鉴权、案件权限、版本和预算校验
      ↓
任务编排／检查点／有限复核
      ├─ 文件检查与只读识别副本
      ├─ 视觉模型／OCR／局部查看
      ├─ 文书结构与案件事实
      ├─ 逐格填写及来源校验
      ├─ 人工决定与适用经验检索
      └─ 原表渲染、组卷和成果验证
      ↓
SQLite 状态与审计＋案件文件目录＋版本化成果
```

### 5.2 状态与失败恢复

任务阶段建议：queued → inspecting → structuring → extracting → reviewing → rendering → draft_ready → awaiting_final_confirmation → finalizing → completed。附加状态：awaiting_user、paused_budget、failed、cancelled。草稿可用性独立保存，不能因进入待核状态隐藏已有效生成的成果。

每个可重复执行步骤记录输入哈希、材料版本、工具/模型/提示/规则版本、输出及副作用提交状态。重复提交复用同一请求标识；本地可幂等步骤允许恢复，云请求超时且服务端是否完成未知时标记 unknown，不自动重复付费。

补件、字段修改或边界修改沿依赖关系只使相关步骤失效；最终确认绑定材料版本、事实修订、模板和规则版本。新版本使旧确认失效，但旧成果保留。运行中对同任务写入使用版本比较与锁，旧页面提交返回冲突并保留用户输入。

## 6 数据契约与接口建议

以下为新增契约设计，不表示接口已经存在。所有记录通过服务端确定 org_id、case_id、task_id，不信任客户端传来的权限范围。

| 对象 | 核心字段 |
| --- | --- |
| SourceFile / SourcePage | file_id、sha256、material_version、page_id、original_page、conversion_version、quality_flags |
| DerivedView | page_id、transform、crop_bbox、coordinate_mapping、engine_version、artifact_hash |
| Document / MaterialGroup | document_id、page_refs、title_candidates、doc_type、case_relation、stage、group_id、boundary_evidence、status |
| EvidenceRef | page_id、bbox、原文或视觉描述、读取方式、材料哈希、文书版本；区分原文与模型释义 |
| FieldDecision | form_id、cell_id、value、display_text、evidence_refs、conflicts、blank_reason、adoption_status、actor、revision |
| ReviewIssue | issue_id、document_id/field_id、reason、impact、options、source_targets、resolution、related_issue_ids |
| AgentAction | action_id、工具参数摘要、输入哈希、结果引用、duration、tokens、budget_reserved、status；不得默认写材料全文 |
| Experience | experience_id、scope、conditions、exclusions、required_evidence、action、source_decisions、version、approval、validation |
| RunManifest | material/rule/prompt/model/template/experience版本、任务阶段、授权范围、请求预算、成果状态 |

来源引用必须指向存在的当前材料；原件缺失或哈希变化不能只靠旧文本继续采纳。人工填写而无材料依据的值应明确标记人工来源，不伪造引用。

| 建议接口 | 行为与约束 |
| --- | --- |
| GET /api/cases/{case_id}/tasks/{task_id}/structure | 返回材料组、文书、页面与候选边界 |
| GET /api/cases/{case_id}/tasks/{task_id}/review | 返回统一核对队列、定位和选项 |
| POST /api/cases/{case_id}/tasks/{task_id}/decisions | 带request_id、expected_revision、material_version；幂等保存人工决定 |
| POST /api/cases/{case_id}/tasks/{task_id}/resume | 检查授权、版本和预算，仅恢复有效的未完成步骤 |
| GET /api/cases/{case_id}/tasks/{task_id}/trace | 返回可读动作摘要、来源和成本，不泄露密钥/内部推理 |
| POST /api/experiences/proposals | 从已确认决定创建候选，不直接启用 |
| POST /api/experiences/{id}/approve 或 /retire | 有权限者操作，要求版本和验收记录；审计可追溯 |

鉴权失败返回401/403；旧版本写入返回409；非法参数返回422；预算/授权不足返回明确业务状态。续跑授权不足属于等待状态，不是系统故障。现有接口尽量兼容，前端逐步迁移。

SQLite采用新增表、索引与可回滚迁移；记录 schema_version。先备份并在副本迁移，历史任务缺字段按 legacy 显示，不通过回填虚构经历使其看起来已经运行新 Agent。

## 8 数据处理与预算边界

云端模式明确显示提供方及发送内容范围；本地模式识别和日志不得静默转云。模型、OCR、向量嵌入、调试追踪和错误上报均纳入出网检查，不能只检查主模型接口。缓存和经验库默认本地按组织隔离。

姓名入口只提供工作区区分，不等于身份认证。真实保密或多人部署要求可靠认证、案件权限及管理员权限；不能以知道他人名字即可进入其案件的方式宣称保密隔离。

每次任务绑定模型请求数上限、复核上限、允许的材料范围和可获得的费用上限。请求发出前预留预算，失败/超时同样记账；没有实际价格数据时只报token和调用量，不编造费用。用户授权次数之外的真实材料云调用须另外明确授权。

2026年10月30日用户确认：DeepSeek单个归档任务最多20次模型调用，覆盖分类、提取、复核和填写；失败/超时计入，已完成响应的缓存回放不计入。新DeepSeek视觉任务冻结此上限，可设置更低值，不能通过重启、重试或规则更新绕过。部署配置`V5_DEEPSEEK_REQUEST_LIMIT`默认20、允许0—20，通用`V5_MODEL_REQUEST_LIMIT`如更低则取更低值；不将云端上限自动套用到Ollama。旧任务不补造历史计数或自动迁移冻结策略；部署前需另行核对其可恢复范围。达到上限保留已完成内容及源页，未处理部分明确标记，不承诺任意页数的卷宗均可在20次内完成，也不将未完成草稿视作正式成卷。此预算决定不扩大真实材料测试授权。

检索缓存键包含组织、材料哈希、版本及工具配置，不跨组织复用客户内容。临时文件、材料、产物和经验均规定保留/删除策略，实施前由管理员确认；过期来源不得因缓存存在而继续可访问。真实材料和私有验收结果不提交公开仓库。

## 9 验收方法与发布门槛

### 9.1 真实验收集

从已有授权材料和用户补充难例建立开发集与保留验收集。按案件划分，不能把同一案不同页面分别放进两组。首批5—10份难例只用于启动，不足以证明所有业务可靠。参考答案由用户确认，不从旧模型结果直接生成。

已有原表保留与移除答案后的自动补填分开验收。移除操作只在受控测试副本进行，保留原件；若把已填答案提供给模型，就不能声称验证了从基础材料自动填表。

不以虚构案件、固定返回值或缓存回放代替真实识别验收。必要单元测试只能证明程序行为；代码、缓存回放、真实模型、原生文档、真实浏览器和真实助理试用分别记录证据。

### 9.2 场景验收矩阵

| 编号 | 场景 | 必须达到的结果 |
| --- | --- | --- |
| A01 | 合同后接借据、登记证明及截图 | 同属证据组但身份分开，合同段不得吞入后续独立材料 |
| A02 | 连续无标题续页或跨页表格 | 依据衔接保留关联，不逐页要求指定类别；不确定范围可追踪 |
| A03 | 手写关键金额/日期有歧义 | 局部检查和佐证后仍不明则留白或请求选择，不猜填 |
| A04 | 横竖混排、倒置及倾斜 | 识别视图方向合理，能定位原页；原件不被增强图覆盖 |
| A05 | 低清、遮挡或破损 | 准确描述无法确定的内容及影响，不生成不存在的信息 |
| A06 | 文件夹文件名误导或单文件混文书 | 文件名仅作线索，内部结构及内容决定归类 |
| A07 | 混入他案材料或重复页 | 不污染本案事实，不静默删除；每页有保留或排除记录 |
| A08 | 证据清单有条目但附件未见 | 明确实际未找到，不制造附件或宣称齐备 |
| A09 | 已有原审批表或部分组合表 | 原件一次入卷，只生成缺失组件，不强制五份Word |
| A10 | 无原审批表、诉状及收费信息完整 | 简介含事实和诉求；收费有完整条件；适用栏目填写、手填区域留白 |
| A11 | 判决后有执行/和解/履行资料 | 结案综合过程和实际结果；未见履行不推定结清 |
| A12 | 补件与人工修改并存 | 只更新受影响自动值，保留人工选择；冲突集中；旧确认失效 |
| A13 | 重复点击、刷新、断网和重启 | 不重复付费/出卷，不丢决定；不确定外部请求不盲目重试 |
| A14 | 新经验发布、冲突与回退 | 只影响适用的新任务；他组织和旧任务不被改写 |
| A15 | Word/PDF/ZIP与目录页码 | 同源内容、原框稳定、无裁字溢出；草稿无新增页码、定稿正文底中连续 |
| A16 | 用户隔离与本地模式 | 越权读取被拒绝；本地处理无云回退；追踪和嵌入同样受控 |

### 9.3 指标定义

- 文书边界：报告错误合并数、错误拆分数及人工确认的文书总数；不能只报告文书数量下降。
- 自动采纳可靠性：错误自动采纳数/已复核自动采纳数，同时报告自动采纳覆盖率；模型置信分数另列。
- 字段完整性：应填且有足够依据的栏目中正确填入的数量/总数；手填、明确不适用和原件保留项单列，不混入分母。
- 关键事实错误：姓名、角色、金额、日期、程序结果等单独报告；已知错误未修复或转为明确待核前，不通过发布。
- 来源与页守恒：每个自动采纳关键值可定位；每个源页有去向；已知遗漏、非授权排除和错误重复为0。
- 用户负担：独立核对事项、原件打开次数、点击数、人工用时；与同一材料的基线比较，不通过隐藏问题降低指标。
- 性能与成本：按页数、材料复杂度及运行环境分组记录OCR、模型、复核、渲染总耗时，调用数和token；样本不足不报稳定P95，不承诺100页一分钟。

发布采用明确验收集：已知关键事实错误、无依据填写、源页静默遗漏、越权访问、未经授权云调用和不可恢复数据丢失均须为0；这只是该验收集的通过条件，不宣称所有案件零错误。广泛准确率和耗时目标在真实基线建立后由产品负责人确认，不预填虚假百分比。

### 9.4 每轮报告及用户决策

每轮提交材料范围、版本、实际调用和耗时；按频次列出最常见的前三类问题，附页码、影响及处理选项。一次错误可能影响多个栏目，应同时报告问题数和受影响数，避免重复计数。

用户决定业务处理后再修改规则，不因模型自我反思直接推广经验。新问题未获得处理意见时，可以修程序异常和整理证据，但不得擅自改变归档约定。失败后不自动追加付费重跑。

不设未经估算的固定工期。按下列顺序推进，每一阶段都须有用户可看到的成果和可复现证据，不能只交测试通过数量。

| M2 Agent与填写 | F04—F06、检查点、有限复核、字段证据、集中核对 | 同案导入到草稿的可用链路，原表内容和留白正确，页面可完成必要选择 |
| M3 经验闭环 | F07、版本快照、审批发布、冲突和回退 | 一条来自真实纠错的经验在另一适用案例中验证；有不适用案例证明不会泛化 |
| M4 成果与扩展 | F08、真实浏览器、失败恢复、五类业务逐类验证 | 完整成果包、场景验收矩阵、版本发布记录；未通过类别明确保留限制 |

P0优先级：材料与来源安全、文书边界、关键字段与留白、原表成果、任务幂等及必要用户决策。P1：经验发布界面、更多复杂版式和业务扩展。P2：本地模型性能优化、安装包和大规模并发。

发布前备份数据库、配置及静态资源，确认无运行任务；试运行采用隔离数据和明确授权。支持关闭新Agent路径回退到旧实现，历史成果保持可访问。回退不得要求删除客户数据或撤销人工决定。
