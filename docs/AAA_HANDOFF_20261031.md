## 5. 当前阻塞及恢复后的建议顺序

1. **先完成按填写任务的阅读调度。** 全页先保留结构和用途判断；核心诉状、裁判、实际办案/执行来源优先；辅助材料只有被关键字段、引用、冲突或办理结果触发时深入读取。明确记录未深读范围，不能一律忽略证据，也不能把未读当无关。
2. **核算完整任务预算，而非只压缩分类。** 分类、字段、有限复核及2次综合写审共享20次；不得通过新任务、重启、隐式重试绕开。不能承诺任意页数和复杂度都能在20次内完成；超限应保留部分结果并准确说明。
3. **以完整表格而非局部候选作为下一可见成果。** 核查案情简介含事实和诉求，审办结果与小结覆盖实际过程；收费条件完整；应填字段不漏，手填与无据内容不猜。逐格记录依据、采纳/留白原因、最终原表位置。
4. **在上述具体改动就绪后，再申请一次范围明确的真实验证。** 先复用已有缓存和响应定位程序问题，避免连续付费重跑。报告最常见前三类问题、来源、影响和处理选项，由用户决定业务约定。
5. **再做原表与网页整链验收。** 看最终Word/PDF的字体、框格、页数、裁字、页码及目录，实际走导入—集中核对—草稿—定稿；记录用户操作负担。通过后才备份并部署，保留旧成果。
6. **M2稳定后补M3闭环和M4覆盖。** 同一真实经验须在另一适用案例及不适用反例中验证；随后按五类业务补验收矩阵。本地化性能和新框架引入不应抢占完整填表这一主线。

这些是恢复后的待办，不是本次执行授权，也不是已经完成的工作。

## 6. 业务规则：必须继承

- 优先保留已有原审批表等，只补缺失组件；存在不代表已审批/签署。
- 内部合同号留空；签名、审批意见、客户评价等需人工确认的格子留空，不代写。
- 复杂风险收费能准确识别结构及条件才填，否则留空；日期有准确、无冲突依据才填。
- 收费以本案合同/补充条款为主；明确对应本案的委托代理通知书也允许作为依据，必须保留条件，不证明合同齐备或已收款。
- 案情简介按立案时视角写事实和诉求；审办结果、结案小结按全案真实办理过程写，不能把终本当清偿。
- 民事案件名称按原告、全部被告、案由组织，不因本方代理立场颠倒角色。
- 明确合同附件随合同；独立借据、登记证明、银行截图保留独立文书，可同属证据组。
- 民事目录按最新批注：所函第7项、普通受理通知第12项；执行受理材料按执行处理。17/18项依实际执行材料判断。
- 草稿不新增归档页码；定稿目录后正文从1开始底部居中，注明与纸质办法页码位置的差异。
- 分层阅读的重要性是对当前填写/核验任务的影响，不等同证据效力；不得用模型自报80%直接替代自动采纳校验。
