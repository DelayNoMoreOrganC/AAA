# 经验治理候选接口（2026-10-30）

当前为内部候选实现，未部署。核心界面未改。**第五轮已接任务固定快照、视觉分类建议和按字段补读；没有真实经验达到发布验收，未证明模型准确率提升。**

## 已实现的范围

- SQLite 新表：`experience_versions`、`experience_evaluations`、`experience_events`。通过现有 `create_all` 在部署后的正常启动中创建；本轮未连接或迁移生产数据库。
- 候选从现有任务的人工目录核对记录 `_review_decisions` 发起，绑定任务、修订及决定摘要。普通用户只能创建自己的本案草稿；律所、通用范围由本组织管理员提议，通用也不跨组织共享。
- 内容不可原地修改；改动创建新草稿，可以关联旧版本。相同来源修订和内容的重复提交返回原记录。
- 生命周期 `draft → validated → approved → active → retired`，每次变更记录操作者和修订号，过期修订拒绝写入。停用后不能直接复活；替代版本须重新审核。
- 验证、批准、发布均检查服务端验收记录：必须匹配规则摘要和评测器版本，至少有另外两个案例的适用与不适用结果、来源/标注/结果指纹及授权检查。
- **HTTP 不提供写入“验证通过”的接口；可信实案评测器尚未实现。**因此目前不能通过正常接口把新草稿发布，不能把技术协议测试算作实案验收。
- 发布前拦截互相矛盾且条件可能重叠的归组/阅读策略。快照构建再次排除冲突双方，避免并发发布或历史异常造成“最新覆盖旧规则”。
- 快照返回组织、案件、规则副本、版本及摘要。新案件启动时写入任务的 `execution_profile`，补件继承父任务版本，历史任务无快照时使用空集合，不追溯套用当前规则。停用不修改已有任务。
- 任务配置根据数据库案件所属组织校验快照，设置中的普通字典不能冒充内部经验上下文。快照摘要绑定模型调用检查点和分析复用条件，失配时拒绝复用；实际视觉上下文必须与检查点一致。

## 当前规则契约

仅开放结构化枚举，不接收任意提示词、客户姓名、文书正文、文件路径或可执行动作：

| 内容 | 当前范围 |
|---|---|
| 业务 | 民事、行政、刑事、非诉、顾问 |
| 条件 | 文书种类、必需观察信号、排除信号 |
| 动作 | 保留明确合同组件、独立成文书、为字段补读、仅保留归档 |
| 字段用途 | 案情简介、结案小结、审办结果、当事人、收费、日期 |
| 强制保护 | 保留组件必须有明确关联；仅归档必须有明确留存用途，并排除相关字段、冲突、模糊、手写、方向未知、核心缺失、边界未决 |

缺少排除条件的观察结果表示“未知”，不当作“没有问题”。规则匹配只表达处理建议，不证明观察真实，不证明签署、送达、履行，也不能覆盖手填留白或原件保护。

当前标签是本模块的路由契约。第五轮已映射诉状、答辩、代理意见、裁判、工作记录及字段用途，但附件/借据/登记证明等细类仍主要作为分类提示，不冒充已完成全类别、模板版本匹配。第六轮接入文书分类修改、字段人工纠正；拆分/合并文书边界的专门决定记录尚未接入。

## 第六轮纠正来源

- `source_kind` 支持 `catalog`、`classification`、`field`，`decision_key` 分别指目录项、文书段身份摘要、字段名。目录中的“等待补充”不是已完成纠正，不作为候选来源。
- 文书分类使用已保存的人工分类记录，验证文件指纹、页段、案型、阶段、目录选项、修订和未决分类状态，不读取原卷或重新OCR。
- 新的普通字段修改与明确清空都记录操作者、任务、案件、机构、材料版本、字段及应用修订；候选必须与当前字段及人工值一致。已经变化、被撤销的纠正不能继续发布。
- 增加 `experience_origins` 保存本组织内的原纠正依据。原记录与摘要分开校验，发布前再次核对当前来源。这里可能含本案字段值，**不会复制进可复用规则、普通经验列表、冻结模型建议或跨机构数据**。
- 旧目录决定或旧字段记录缺少材料/操作者绑定时可保留待审候选，但不能进入验证/批准/发布。旧草稿没有来源表记录的也需重新检查，不自动补造绑定。
- 该绑定证明纠正来自哪一次材料和操作，不证明人的决定必然正确；仍需适用和不适用实案评测。

## 第五轮识别接入

- 分类请求带上当前业务适用的冻结规则及优先级说明，不发送来源案件、机构信息或历史正文。规则要求先检查当前材料；归组仍通过原有有界复核和引用验证，不由经验代码直接拆分、合并。
- 阅读计划使用当前文书观察及字段冲突匹配经验。匹配 `read_for_field` 时可提升阅读优先级、补入对应原表字段；若原计划未选页，至少恢复首尾页供核查。未知观察不能作为否定条件。
- 留存建议不能删掉原计划选读页，经验不能直接写事实、改变原件、覆盖手填留白或跳过既有校验。日期等字段即使被列入核查，仍受现有证据与留白规则约束。
- `_experience_policy` 记录快照摘要、冲突和送入分类阶段的规则ID；阅读计划另记匹配条件、字段和“要求阅读，尚非事实核验”的状态。记录纳入每次分析来源作用域，补件不混用局部文书ID。
- 历史父任务的经验版本继续用于补件；显式升级旧案件规则版本的操作尚未开放，不会因管理员发布而自动收费重跑旧案件。

## 后台接口

- `GET /api/experiences`：普通用户看自己创建的记录，管理员看本机构记录；每页最多100条。
- `GET /api/experiences/sources/{task_id}`：按原案件权限返回可选择的纠正类型、键及来源状态，不返回字段值或客户资料。
- `POST /api/experiences`：建立候选；额外提交 `passed`、提示词等未定义参数会被拒绝。
- `POST /api/experiences/{id}/transition`：管理员请求状态变更，不能跳过校验、伪造评测结果或修改规则内容。
- `POST /api/experiences/{id}/routing-precheck`：管理员提交当前规则修订号及2—12份独立案例的人工参考标注，执行材料指纹与条件匹配预检。它不生成可发布回执，不调用模型或OCR。

尚未接入助理反馈入口，不要求用户在现有页面增加操作。

## 第十五轮：适用例／反例预检

新增 `experience_precheck.py`，仍未部署。不新增表，预检写入现有 `experience_evaluations`，类别为 `real_case_routing_precheck`；现有发布门槛明确不接受它。

- 标注必须包含 `task_id`、`task_revision`、`file_id`、从1开始的 `start_page/end_page`、`document_kind`、`signals`、`expected_applicable`、`expected_action`、`expected_target_fields`、`reference_reviewed: true`。不接收 `passed`、提示词、客户事实或任意文件路径。
- 必须有适用及不适用标注，且来自原纠错案件之外的不同案件。规则涉及的所有必要／排除信号均须明确为布尔值；未知不能充当合格反例。
- 标注是管理员对实际材料的判断，不是系统自动生成的真值；它的可靠性仍需业务审核。预检证明规则是否符合这些标注，**不证明模型能从图像正确识别条件，也不证明填写结果改善**。
- 先检查组织权限、规则修订、原纠错绑定、任务修订及页范围，再读取文件指纹。原案例及参考任务须处于待核对或完成状态，不能使用正在处理的任务。材料必须仍是该案件的有效文件，路径必须位于受管资料目录中，重新计算SHA256，不用旧缓存冒充当前字节。
- 不同案件编号或文件名不能绕过同源文件检查。任意材料字节重叠会返回 `EXPERIENCE_OVERLAPPING_MATERIALS`；这是保守的重叠拦截，并不证明案件相同。含相同公共空白模板的案例也可能被拦截，当前没有自动豁免；重新扫描但内容相同的文件也不能只靠SHA256识别，仍需人工确认案件独立性。
- 程序比较实际是否匹配、动作、目标字段，不采用调用者指定的通过结论。错误目标字段会得到失败报告。报告仅保存标注、编号、指纹和检查结果，不复制原文或磁盘路径。
- 同样输入和结果返回同一回执；记录本机构操作者。回执始终 `publish_eligible: false`、`recognition_accuracy_verified: false`，不能推动经验进入validated、approved或active。没有改变已有任务冻结的规则。

隔离验证使用三份此前授权的真实PDF，仅校验字节和页数；账号和标签均为协议夹具，不是已经人工审核的案例答案。21项新接口／存储／权限检查及34项既有治理检查通过，无模型、OCR或生产数据库操作。下一步需以真实人工标注为基准，对候选经验在识别、补读与最终填写中的效果做对照，再补齐发布级评测器。

## 验证与下一步

### 第三十六轮：原始采纳字段对照

视觉Agent现在将逐栏采纳值记录到`_machine_field_candidates`，与原材料作用域、经验版本一起进入不可由普通字段编辑覆盖的trace。记录时点是Agent完成提取/综合撰写之后、后续规范化和人工编辑之前；**它不是最终Word/PDF内容或版式回执**。既有历史结果没有这份记录时，不能从用户已修改的内容反推“模型原答案”。

记录包括值、原表留白策略投影、物理来源页、冲突、人工介入和栏目规则摘要。不会在诊断中重复保存原文引文；这些仍保存在原来源依据中。内部合同号等原候选可保留用于关联，但空白策略投影不会把它当作应输出的编号。综合撰写字段通过原有依据验证扩展多页引用。

新增管理员`POST /api/experiences/{identity}/field-comparison`。请求外层仍为`revision`和`references`；每个参考含基线/候选任务ID及修订、`expected_applicable`、`reference_reviewed: true`，将上一节的`documents`替换为`cells`：

```json
{
  "field": "委托人",
  "mode": "exact",
  "accepted_values": ["人工核实的可接受值"],
  "allowed_sources": [{"file_id": "当前材料ID", "page": 1}]
}
```

- `exact`：值须等于人工参考中的某个可接受值，且记录的物理来源均在允许页内。
- `blank`：策略投影应为空；`accepted_values`和`allowed_sources`均为空数组。
- `grounded_nonempty`：非空且有允许页内来源；`accepted_values`为空。**这种检查不证明小结语义完整或每一句都被来源证实。**

适用于`read_for_field`/`retain_only`经验，复用独立案例、来源哈希、修订、权限和冻结经验校验。报告列明已评、未评栏目；不读取人工投影值作为原始模型值，不返回客户文字，不发送API/OCR、不新增测试任务。两次字段规则摘要不同则拒绝混比。

返回`real_case_field_comparison`，仅`all_selected_field_checks_match`表示指定检查通过；`field_accuracy_verified`、`semantic_completeness_verified`、`native_output_verified`和发布资格均为false。发布级评测仍需受控候选执行、独立人工参考、完整语义及原表验收。

144核心和83后台程序检查通过，无新真实材料读取或模型调用，无UI、生产数据或部署变化。

### 第三十五轮：模型原始文书边界对照

新增 `POST /api/experiences/{identity}/boundary-comparison`，管理员使用，核心UI不变。请求包含规则`revision`以及2—12项`references`；每项包含：

- `baseline_task_id`、`baseline_revision`、`candidate_task_id`、`candidate_revision`：同一案例、相同来源的前后任务。
- `expected_applicable`、`reference_reviewed: true`：人工判断的适用性与已经核对参考；不是模型自评真值。
- `documents`：覆盖本案全部文件，每项为`file_id`与`ranges`；页段从1开始连续覆盖整个文件，例如`[[1,3],[4,5]]`。调用者不能提交预测结果或`passed`。

仅适用于`keep_component`和`separate_document`经验的边界比较。基线快照不得含被评经验；候选快照须含相同规则摘要，其余经验保持一致。模型配置及分析版本须相同，但当前没有受控实验执行器，不能因此宣称唯一变量已严格隔离。

程序读取任务受保护的原始模型trace，而非人工修改后的`doc_spans`或目录投影。校验来源身份、页覆盖、经验快照、任务修订；逐断点比较漏分和误拆，并保留未解决的边界复核数量。不同页上的错误不能只因数量相同而算作无退步。

对照使用原纠错案例之外的独立适用例及反例，重新计算当前文件哈希，同源字节不能作为独立样本。校验全部权限和任务引用后才读取文件，异步读取后再核对修订与权限。报告没有原文、路径或客户字段值。接口只分析已有结果，不创建测试任务、不申请模型调用、不修改原案件或经验状态。

返回类别为`real_case_boundary_comparison`，保存于现有`experience_evaluations`，相同输入幂等。**它仍不是发布回执**：`publish_eligible`、`causal_effect_verified`、`controlled_experiment_verified`及`field_accuracy_verified`均为false。旧无scope结果、多补件trace及预算未完成结果暂不作为完整对照输入。

17项核心及15项后台记录/存储/权限/HTTP协议检查通过。测试中的页段、上下文与账号是协议夹具，未执行虚构卷宗识别，也没有新增真实业务标注或真实模型验收。受控候选运行、字段和原表输出比较、独立人工参考以及发布级评测仍待完成，不能据此宣传经验自动升级已实现。

在内存SQLite、隔离FastAPI应用上验证权限、重复提交、状态顺序、过期修订、冲突、组织隔离与接口参数。测试用的是账号/任务协议夹具，不是虚构卷宗识别；人为构造的验收凭据仅用于内存中的状态机测试，未写入真实数据库、未证明识别有效。

第五轮补充26项针对性验证：隔离SQLite持久化、实际任务配置入口、父子快照继承、检查点身份变化、缓存失配拒绝，以及已有真实分类回复的协议回放、真实文书结构的字段路由保护。没有新增模型、OCR调用，未进行网页全流程验收。

第六轮使用真实历史文书结构调用现有分类修改逻辑，并在隔离数据库验证来源入库、撤回/改值/换材料拦截、留白保留、私人依据完整性及HTTP权限，16项检查通过。这些是技术协议变体，不是重新识别实例，不是新业务标注，不写原案件。

下一步连接可信保留集评测器，完善边界纠正来源、规则范围/模板映射和管理员冲突处理。使用真实材料验证前沿用授权与次数限制。没有实案适用/不适用对照结果前不发布经验，更不能宣称模型已自我训练。
