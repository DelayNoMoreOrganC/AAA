## 1. 结论

外置目录是此前开发时保留的模板参考源，项目内 `templates/` 是当前运行版。两者目录结构一致，但不能把外置目录整体覆盖回项目：

- 共 16 个文件：10 份旧版 Word `.doc`、5 份 manifest JSON、1 份 manifest 说明。
- 9 个文件逐字节一致：8 份 `.doc`（除民事、行政卷内目录外）和 manifest `README.md`。
- 5 份 manifest JSON 语义完全一致，差异仅为 CRLF/LF 换行和文件结尾。
- `卷内目录_民事.doc`、`卷内目录_行政.doc` 二进制不同；转为 DOCX 后表格文字、19 行结构、列宽和页边距一致，差异主要位于旧式 Word 二进制版式/元数据。
- 本次 LibreOffice 核对中，项目运行版的上述两份 `.doc` 出现显示异常及空白第二页。它们在 Windows Word/WPS 路径中仍由现有代码压页，但不适合作为 macOS/Linux 运行时自动转换 HTML/PDF 的基础。

机器可读索引见 [`templates/reference-index.json`](../templates/reference-index.json)。

## 2. 权威来源顺序

出现冲突时按以下顺序处理：

1. [`docs/归档生成标准.md`](归档生成标准.md)：卷宗顺序、系统表字段和业务验收规则。
2. [`archive_catalog.py`](../archive_catalog.py)：五类案件当前 seq、卷末插入和目录裁剪逻辑。
3. [`templates/bundled/`](../templates/bundled)：Windows Word/WPS 运行路径当前使用的版式文件。
4. [`templates/manifests/`](../templates/manifests)：哪些单元格可填、清空、顺序填充或必须固定。
5. [`field_mapping.py`](../field_mapping.py)：LLM 通用字段到模板占位符的映射。
6. `/Volumes/曾进朗/templates`：历史参考和视觉比对源，不直接参与运行。

V6 清理已移除 0619 开发记录与 V4 循环计划。解释占位符、模板清理、页序和字段质量时，以当前代码、测试与本页列出的业务标准为准。

## 3. 文件分类

### 3.1 五份可填写系统表

| 表格 | 业务位置 | Manifest | 表格结构 | 可填/人工留空位置 | 页数预算 |
|---|---|---:|---:|---:|---:|
| 档案卷宗 | seq0，卷宗封面 | v3 | 1 表、14 行 | 15 | 1 |
| 立案审批表 | seq1，正文最前 | v4 | 1 表、10 行 | 10 | 1 |
| 质量监督卡 | 卷末，连同委托人须知 | v3 | manifest 主表 3 行 | 3 | 2 |
| 送达材料清单 | 卷末系统表，依《归档生成标准》纳入整卷及目录 | v3 | 1 表、11 行 | 5 个顺序格 + 3 个段落格 | 1 |
| 结案报告表 | 卷末结案系统表 | v3 | 1 表、10 行 | 9 | 1 |

说明：

- `fill`：程序预填，浏览器允许人工修订。
- `seq_fill`：同一字段按多行顺序填入，如多份法院文件。
- `clear`：Word 流程会清空；改为浏览器表格后宜作为允许人工填写的空白输入格。
- `fixed` / `header`：固定文字或表头，不允许编辑。
- 质量监督卡的 manifest 只描述需要程序写入的主表位置，后续固定监督问题和“委托人须知”仍以原表视觉版式为准。

### 3.2 五份卷内目录

| 案件类型 | 文件 | 当前用途 |
|---|---|---|
| 民事 | `卷内目录_民事.doc` | 固定目录名称，仅回填页码 |
| 刑事 | `卷内目录_刑事.doc` | 固定目录名称，仅回填页码 |
| 行政 | `卷内目录_行政.doc` | 固定目录名称，仅回填页码 |
| 非诉 | `卷内目录_非诉.doc` | 固定目录名称，仅回填页码 |
| 法律顾问 | `卷内目录_顾问.doc` | 固定目录名称，仅回填页码 |

卷内目录没有对应 manifest，当前由 `catalog_toc.py` 按案件类型选择模板并只填写页码列。HTML 化时应单独设计“目录布局 JSON”，不要与五份系统表的字段 manifest 混用。

## 4. 五份 manifest 的实际含义

外置目录与项目内的 5 份 JSON 经规范化排序后完全相同。开发文档确实使用了这些 manifest：

- `template_manifest.py` 加载并校验角色。
- `manifest_word_fill.py` 根据 `fill/clear/seq_fill` 限定写入范围。
- `field_mapping.py` 将统一案件字段展开成旧 Word 占位符。
- `lian_approval_fill.py` 对立案审批表 1–10 号格做专用映射。
- `scripts/verify_template_fill_batch.py` 检查关键槽位不得残留占位符或“待确认”。

一个需清理的历史元数据：`立案审批表.json` 的 `source_doc` 仍写着 `立案审批表_0606.doc`，但当前实际运行文件已统一命名为 `立案审批表.doc`。这是历史备注，不应据此恢复已清理的旧文件。

## 5. 浏览器原表版式转换（2026-07-15 已落地）

[`wordFormLayouts.ts`](../web/frontend/src/components/wordFormLayouts.ts) 已将五份系统 Word 模板转换为浏览器布局定义，记录 A4 分页、列宽、合并单元格、行高、固定文字和可编辑单元格。[`PreviewFieldEditor.vue`](../web/frontend/src/components/PreviewFieldEditor.vue) 负责将布局渲染成原表样式。

转换使用以下权威来源组合：

- manifest：决定哪个物理格可编辑；
- `field_mapping.py` / `preview_fields.py`：决定该格绑定哪个统一字段；
- 原 `.doc`：只作为视觉尺寸、边框、字体和固定文字参考；
- `docs/归档生成标准.md`：决定最终业务字段和卷内位置。

## 6. 当前 HTML 化实现

当前保留原 Word 与 manifest，并新增网页布局定义：

```text
templates/
├── bundled/          # 当前 Windows Word/WPS 兼容模板，不覆盖
├── manifests/        # 可填写位置与占位符语义
└── reference-index.json

web/frontend/src/components/
├── wordFormLayouts.ts       # 五份 Word 表格的声明式布局
└── PreviewFieldEditor.vue   # 原表渲染、无边框编辑与保存
```

布局定义记录：

- A4 页面、页边距和页数；
- 表格行列、`rowspan/colspan`、列宽、最小行高；
- 固定文字、字体、字号、对齐、边框；
- `role` 与统一 `field_key`；
- 单行或多行输入、最大字数和打印规则。

浏览器中仅 `fill/clear/seq_fill` 渲染透明无边框输入框；`fixed/header` 只显示。输入框聚焦时可显示浅色辅助框，失焦和打印时完全隐藏。
